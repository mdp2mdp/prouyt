# Публикация на GitHub Pages и переключение домена prouyt.ru

## 1. Первая публикация на github.io

Выполняется один раз.

1. На GitHub в репозитории `mdp2mdp/prouyt` откройте **Settings → Pages**.
2. В поле **Source** выберите **GitHub Actions** (не «Deploy from a branch»).
3. Отправьте код: `git push -u origin main`.
4. Во вкладке **Actions** откройте запуск «Deploy to GitHub Pages». Когда оба шага (`build`, `deploy`) станут зелёными, сайт появится по адресу **https://mdp2mdp.github.io/prouyt/**.
5. Проверьте сайт на телефоне и на компьютере: главная, раздел, карточка, звонок по `tel:`.

Каждый следующий `git push` в ветку `main` собирает и публикует сайт автоматически (1–2 минуты).

Если репозиторий приватный, Pages на бесплатном тарифе не заработает: репозиторий должен быть публичным (или нужен платный тариф).

## 2. Как обновлять сайт

| Что менять | Где | Команды |
|---|---|---|
| Цена, текст модели, характеристики | `src/data/products.json` (или `scripts/overrides.json`, если правка поверх docx/xlsx; тогда `npm run data`) | `git add -A && git commit -m "..." && git push` |
| Контакты, меню, юридические тексты, переключатель цен (`priceMode`) | `src/data/site.json` | то же |
| Фото | положить файлы в `_source/проуют диваны фото/<папка модели>/`, затем `npm run data && npm run images` | `git add -A`, commit, push |

Перед пушем полезно запустить `npm run audit`: он собирает сайт и проверяет ссылки, картинки, `title`/`description`, телефон и почту.

## 3. Подключение домена prouyt.ru без простоя старого сайта

Пока домен указывает на старый хостинг, сайт на github.io живёт отдельно, ничего не ломая. Порядок переключения:

**Подготовка (за 1–2 дня).**
1. В панели DNS домена уменьшите TTL записей `A`/`CNAME` до 300 секунд. Тогда переключение распространится за минуты, а не за сутки.
2. Выпишите все текущие DNS-записи (особенно `MX`, `TXT` для почты: их мы не трогаем).
3. Убедитесь, что сайт на github.io полностью принят, а в `ВОПРОСЫ_ЗАКАЗЧИКУ.md` закрыты критичные вопросы.

**Переключение.**
4. В репозитории: **Settings → Secrets and variables → Actions → Variables**, добавьте две переменные: `SITE_URL = https://prouyt.ru` и `BASE_PATH = /`.
5. **Actions → Deploy to GitHub Pages → Run workflow**: сайт пересоберётся с путями для корня домена. Файл `CNAME` в репозитории не нужен: при публикации через GitHub Actions домен задаётся только в настройках Pages.
6. **Settings → Pages → Custom domain**: введите `prouyt.ru` и сохраните. Пока DNS не переключён, github.io-адрес начнёт перенаправлять на prouyt.ru (старый сайт). Поэтому пункты 4–7 делайте подряд, в спокойное время.
7. В DNS у регистратора:
   - для `prouyt.ru` (корень) замените записи `A` на четыре адреса GitHub Pages:
     `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`
     (по желанию добавьте `AAAA`: `2606:50c0:8000::153`, `2606:50c0:8001::153`, `2606:50c0:8002::153`, `2606:50c0:8003::153`);
   - для `www.prouyt.ru` создайте `CNAME` на `mdp2mdp.github.io`;
   - `MX`, `TXT` (почта) не меняйте.
   Актуальные адреса сверьте с документацией GitHub («Managing a custom domain for your GitHub Pages site»).
8. Подождите, пока в **Settings → Pages** рядом с доменом появится зелёная отметка «DNS check successful», затем включите **Enforce HTTPS** (сертификат выпускается автоматически, это занимает от нескольких минут до часа).
9. Проверьте https://prouyt.ru и https://www.prouyt.ru (должен перенаправлять на основной адрес).

**После переключения.**
10. Оставьте старый хостинг ещё на 3–7 дней: если что-то пойдёт не так, достаточно вернуть старые `A`-записи.
11. Вернув TTL к обычному значению (3600 и выше), добавьте сайт в Яндекс.Вебмастер и Google Search Console, отправьте `https://prouyt.ru/sitemap.xml`.
12. Структура адресов нового сайта отличается от старого. Если на старый сайт были внешние ссылки, их нужно сопоставить с новыми страницами (отдельная задача: пришлите список старых адресов).

**Откат.** Верните прежние `A`-записи у регистратора и удалите поле Custom domain в Settings → Pages. Чтобы сайт снова открывался по адресу с `/prouyt/`, удалите переменные `SITE_URL` и `BASE_PATH` и запустите workflow заново.
